## 2. Architecture

### Final repository format & location

`tools/level_editor/terrain_repository/repository.json` — one deterministic
JSON document, `schemaVersion` 1:

```
{ "schemaVersion": 1,
  "assets": [ { "id": "asset_0001", "name": "...", "notes": "...",
               "tags": [...],
               "native": { "width": 16, "height": 32,
                           "pixels": [ "0011223300112233", ... 32 rows ] },
               "provenance": { "sourcePack", "sourceTileIndex",
                               "sourceCoords", "sourceTileSize",
                               "licenceNote", "localSourcePath"? } }, ... ] }
```

Assets sorted by id, `sort_keys=True`, **no timestamps** — re-saving an
unchanged repo is a no-op diff. Assets carry LOGICAL pixels (0..3) only, never a
live char code. Persistent across editor projects; not in generated engine
source. Not committed by this task (created on first "Save to repository…").

### Project format changes (V4)

`formatVersion 4` adds `levelMetatileSet` — up to 64 entries, each
`{ name, native:{width:16,height:32,pixels:[32 × "0".."3" strings]},
source: null | {repositoryAssetId, provenance} }`. It is the authored source of
truth; `tileset` (packed glyph bitmaps + metatile defs) is a **derived cache**,
regenerated by `repack_tileset_from_metatile_set` on every native edit or
repository-asset add. `SUPPORTED_FORMAT_VERSIONS = (1,2,3,4)`.

V1/V2/V3 files load unchanged: the packed `tileset` is kept **byte-for-byte**
and a native `levelMetatileSet` is *derived* from it (each metatile def's 16
glyph codes → their 8-byte bitmaps → a native 16×32 grid; names default to the
historical `METATILE_NAMES`). A migrated level renders and exports exactly as
before until a metatile is edited. Adding a repository asset **snapshots**
(deep-copies) its native pixels + provenance into the project, so a later
repository edit or delete cannot break a level build. `MACH` stays a terrain
metatile (name index 14), never reinterpreted as a gameplay object.

### Live metatile representation

`native_metatile.py`: 16 logical multicolour pixels across × 32 rows, values
`0,1,2,3` (0 = `$D021`, 1 = `$D022`, 2 = `$D023`, 3 = colour-RAM character
colour). Char cell `(cr,cc)` covers native rows `cr*8..cr*8+7`, cols
`cc*4..cc*4+3`; its 8 bytes pack each row as
`(p0<<6)|(p1<<4)|(p2<<2)|p3`. `pixels_to_glyphs` / `glyphs_to_pixels`
round-trip losslessly.

### Glyph packing / dedup

`pack_metatiles(native_grids)` → `{glyphCount, glyphs, metatileDefs}`.
Identical 8-byte glyph bitmaps share one code; repeats within a metatile and
across metatiles reuse IDs; glyph order is first-seen and deterministic; the
glyph list is padded to a multiple of 8 (engine copies terrain glyphs in
64-byte chunks). `GlyphBudgetExceeded` is raised — never a silent alias, drop
or approximation — when a level's metatiles need more than the 64-slot terrain
glyph namespace (codes 160..223). The editor shows `Metatiles: N / 64` and
`Terrain glyphs: U / 64`, and per candidate metatile
`16 cells, R existing reused, X new unique required`. `export_readiness_errors`
hard-blocks export of a level over budget.

### Generated source ownership

Unchanged by this task. Char codes 160..223 remain the permanent 64-slot
terrain glyph namespace, already level-owned via generated `stage_charset.asm`
(from Phase 1). `stage_charset.asm` still emits only `terrainGlyphs`
(codes 160..); HUD (128..159), diagnostic (224/225), shared turret body
(226..229) and starfield (240..251) glyphs are untouched. The editor never
patches `main.asm`; every generated byte count / label keeps its compile-time
`.error` guard. `stage_config.asm` gains `.const STAGE_METATILE_COUNT`
(1..64, the level's real count — no scattered magic 16/64).

### Engine metatile-definition lookup

`decodeStageCharacterRow` previously formed the `metatileDefs` offset as an
8-bit `id*16 + subrowOffset`, correct only for id 0..15. It now:

1. reads the stage row's 10 metatile IDs into `BG_ROW_IDS` (a 10-byte scratch
   in the `$2920` segment next to `BG_INCOMING_ROW` — the `$2000` engine-state
   block is full), freeing `TEXT_SRC`;
2. per column builds a 16-bit pointer
   `TEXT_SRC = metatileDefs + (id<<4) + BG_TILE_ROW_OFS`
   (high byte `id>>4 + >metatileDefs`; low-byte carry folded with `bcc/inc`)
   and copies 4 bytes via `lda (TEXT_SRC),y`.

Legal NMOS 6502 only; ±128 branch range respected; the 16-bit
logical-row / metatile-row / row-base arithmetic, the scroller, the
BUILD/LIVE plan, `prepareBackgroundCoarse`/`finishBackgroundCoarse` and
descending-scroll semantics are unchanged. Cost:
`decodeStageCharacterRow` ~1050 → 1697 cycles.

### Memory-layout impact / final max stage rows

`metatileDefs + stageMetatileRows` occupy `$6600..$8800`
(`$2200` = 8704 bytes; `background_turrets.asm` begins at `$8800`). The def
table is variable length (`STAGE_METATILE_COUNT * 16`, no padding). The
64-metatile worst case is a 1024-byte table, leaving
`(8704 − 1024) / 10 = 768` whole 10-byte rows.

**`ENGINE_MAX_STAGE_ROWS = 768`** (was 844). The editor uses this uniform
worst-case bound so stage height never depends on the tileset size. The
engine's own `.if (STAGE_TEST_END > $8800) .error` is label-based and remains
exact (a 16-metatile level could assemble to 844; the editor deliberately does
not allow it). 769 rows with a 64-def table fails assembly with
`"Metatile stage data collides with the background turret segment ($8800)"`.
No protected runtime code was moved; no broad memory-map redesign.

## 3. Editor UX

- **Source-sheet import** (`workshop_ui.ImportDialog`): choose a PNG, set tile
  W/H (default 32×32), slice; a scrolling grid of cached-thumbnail tiles;
  click a tile → opens the Workshop with that source. Incomplete edge cells
  produce a visible warning line; no short/cropped tiles.
- **Tile browser**: cached `PhotoImage` thumbnails, responsive with the 120-tile
  fixture / DithArt sheet.
- **Conversion**: deterministic nearest-colour of the source tile to the FOUR
  colours the current project palette uses (the one editor C64 table). 32→16
  horizontal pair-average (documented). A starting point only.
- **Manual editing** (`workshop_ui.NativeMetatileEditor`): zoomed 16×32 paint
  canvas; 4 logical swatches shown in the current palette but storing indices
  0..3; click and drag to paint; visible 4×4-char boundary guides (toggle);
  undo/redo; source preview alongside; live glyph-cost readout.
- **Repository save**: on Workshop save, "Save to repository…" stores the native
  derivative with a provenance prompt (asset name required; source pack, tile
  index/coords, licence note, notes/tags optional).
- **Level-set selection**: the metatile palette lists the level metatile set
  (up to 64, scrollable) with per-entry names; click to select for painting.
  Buttons: **Workshop…** (edit the selected metatile), **New** (blank),
  **Import PNG…**, **From repo…** (adds a snapshot), **Rename…**,
  **Trim unused** (drops only *trailing* unused metatiles — IDs are never
  silently renumbered; a metatile below a still-used higher ID must be
  repainted first).
- **Glyph-budget display**: `Metatiles: N / 64   Terrain glyphs: U / 64` above
  the palette and in the status bar; per-metatile cost in the Workshop.

## 6. Notes / limitations

1. **Uniform 768-row cap.** The editor caps every level at 768 metatile rows
   (the 64-metatile worst case) even though a small-metatile level could
   assemble taller. Deliberate — one honest bound, no per-project recomputation.
   Intended levels are ~188–200 rows.
2. **Repack may re-order a hand-authored glyph set.** Editing a metatile in the
   Workshop triggers a repack that collapses identical bitmaps; the render is
   visually identical but the exported `terrainGlyphs` bytes can differ from a
   pre-edit export. Migrated levels that are never edited export byte-identically.
3. **`check_scroll_capture --stress`** shows 4 transient pixel hiccups at one
   raster line during one coarse transition — the pre-existing artefact noted in
   `docs/encounter-budget-worklog.md`, not a regression (the plain capture is
   clean across 76M pixels / 87 wraps).
4. **Stale generated `level1/` re-synced.** Documented in §1; `level.json`
   authoring content was not altered beyond the automatic V3 → V4 migration.
5. **Repository file** is created on first use ("Save to repository…"); it is
   not part of this change set and is not committed.

No stop condition from the task's §42 was hit: no broad raster/scroller
redesign, no protected-code move, deterministic migration, no illegal 6502, no
charset streaming/banking, no third-party art bundled, and the actual repository
state matched the prompt's model (Phase 1 already level-owns the terrain glyph
namespace).
